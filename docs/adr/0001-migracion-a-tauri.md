# ADR 0001 — Migración de Electron a Tauri 2 (versión 2.0.0)

- **Estado:** aceptada (noviembre de 2026).
- **Afecta a:** todo el repositorio. `src-tauri/` sustituye a `electron/`; `src/api/backend.ts` sustituye a `window.electronAPI`.

## Contexto

La versión 1.x usaba Electron 41, better-sqlite3 y electron-updater. Electron quedó fijado en la 41 porque better-sqlite3 no publicaba binarios para el ABI de Electron 42. Los instaladores pesaban más de 100 MB (Chromium incluido). El objetivo era pasar a Tauri 2 con Vue 3, TypeScript, Pinia y Tailwind CSS 4, sin perder datos ni comportamiento.

## Decisión

1. **Tauri 2 estable** (crate `tauri` 2.12, CLI 2.12). Nunca Tauri 3 alpha. El backend vive en `src-tauri/` (Rust, edición 2024, `rust-version` 1.90).
2. **SQLite en Rust** con `rusqlite` 0.42 (`bundled`). Hay **una sola conexión** en el estado de Tauri (`Database { conn: Arc<Mutex<Option<Connection>>>, path }`). `None` significa «cerrada» (durante una restauración, o si la BD no abrió).
3. **SQL genérico con la semántica de better-sqlite3.** `db_query`, `db_get` y `db_run` enlazan los números como REAL, rechazan booleanos, arrays y objetos, y devuelven los mismos textos de error. Así las vistas que ya usaban SQL directo no cambiaron.
4. **El módulo de cuenta de cobro se portó a Rust con paridad exacta** (`cuenta_de_cobro.rs`, `money.rs`, `types.rs`). Usa BigUint para el redondeo half-up, centavos en u64 y `ryu-js` para formatear como `Number#toString`. El harness de integración de la 1.x pasó a `cargo test` (`src-tauri/tests/`).
5. **Migración de datos.** En el primer arranque se copia la BD de Electron, sin modificar ni borrar el original. Primero se busca en `cuenta-cobro` y luego en `CuentaCobro`, dentro de la carpeta de configuración del sistema. La copia se hace con `VACUUM INTO` y, si falla, con una copia cruda que incluye `-journal`/`-wal`. Después se valida y se renombra de forma atómica.
6. **Frontend.** `src/api/backend.ts` es el único módulo que importa `@tauri-apps/api/core`. El estado compartido vive en stores de Pinia (`profile`, `clients`, `bankAccounts`, `theme`, `updater`). Tailwind 4 se usa en modo CSS-first, sin `tailwind.config.js`.
7. **Versión 2.0.0.** La release puente de Electron (1.0.12) solo avisa cuando existe una versión con major ≥ 2.

## Divergencias aceptadas respecto a la 1.x

- **Carpeta de datos nueva** (`com.cuentacobro.app`). En macOS, Finder la muestra como si fuera una app, porque el nombre termina en `.app`. Para abrirla: `open ~/Library/Application\ Support/com.cuentacobro.app`, o clic derecho → «Mostrar contenido del paquete».
- **El tema vuelve a «Sistema»** la primera vez: la preferencia vivía en el `localStorage` de Electron, que tenía otro origen.
- **Restaurar con error** reabre la conexión (Electron la dejaba cerrada hasta reiniciar). Respaldar o restaurar sobre el mismo archivo omite la copia, porque copiar un archivo sobre sí mismo lo truncaría.
- **Errores en el cable**: Rust rechaza con un string, sin el prefijo `Error invoking remote method`. Los errores de E/S traen el texto de Rust (`Permission denied (os error 13)`) en vez del de Node.
- **Actualizaciones**: el diálogo pregunta antes de descargar y muestra el progreso. Ya no hay notificación del sistema en inglés. En macOS, si se cierra la ventana y se reabre desde el Dock, el chequeo de actualizaciones vuelve a correr (cada ventana tiene su propio estado JS).
- **Atajos del menú de Electron**: se conserva el zoom (R30). Los de recargar y abrir DevTools no se replican.
- **PDF**: lo genera el motor de impresión de cada sistema (WKWebView, WebView2 o WebKitGTK), no Chromium. El resultado puede variar levemente entre sistemas.
- **Diálogo animado** a 200 ms en vez de 150 ms (Tailwind 4 + `tw-animate-css`).

## Consecuencias

- Los usuarios de la 1.x no reciben la 2.x por electron-updater (`latest.yml` frente a `latest.json` firmado). Hace falta la release puente 1.0.12 o reinstalar a mano. En macOS siempre hay que reinstalar a mano.
- Las llaves del updater son críticas: si se pierde la privada o su contraseña, no se pueden publicar más actualizaciones para la 2.x.
- El PDF nativo de Windows y Linux solo se verificó compilando. Si falla, el plan B es `PdfWindowMode::Offscreen` en `src-tauri/src/pdf/mod.rs`.
- El CI de Linux necesita `libwebkit2gtk-4.1-dev` y el resto de prerrequisitos de Tauri incluso para `cargo test`.
